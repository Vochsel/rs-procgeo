Geometry Model

The central data structure: points, vertices, primitives, attributes, and groups.

Geometry Struct

Geometry is the central container that ties together all geometric data. It owns five subsystems: point storage (SoA positions), vertex storage (topology connectors), primitive storage (polygons), an attribute map (typed per-element data), and a group map (named boolean selections). Every SOP takes one or more &Geometry inputs and produces a new Geometry as output — geometry is the universal currency of the pipeline. 

pub struct Geometry {
    points:     PointStorage,
    vertices:   VertexStorage,
    primitives: PrimStorage,
    attributes: AttributeMap,
    groups:     GroupMap,
}

Create an empty geometry with Geometry::new(), or pre-allocate with Geometry::with_capacity(points, prims) when you know the expected size up front.

Element Hierarchy

ProcGeo follows the same element hierarchy as Houdini. Points carry position, vertices connect points to primitives, and primitives define topology.

Element Handle Storage Key Methods
Point PointHandle(u32) SoA (x[], y[], z[]) add_point, point_pos, set_point_pos
Vertex VertexHandle(u32) (PointHandle, PrimHandle) pairs vertex_point(), vertex_prim()
Primitive PrimHandle(u32) Enum (Polygon) add_face, prim_vertices, prim_points

Points

Point positions are stored in a Structure-of-Arrays (SoA) layout: three separate Vec<f32> for x, y, and z. This design keeps each coordinate channel contiguous in memory, which is critical for two reasons:

  • SIMD — operations like bounding-box computation or transform can process 4/8/16 x-values at a time using SIMD intrinsics, because the data is already packed in lane-friendly order.
  • Cache efficiency — when an algorithm only needs one axis (e.g. height-based filtering on y), it reads a single dense array instead of striding over interleaved (x, y, z) tuples.

PointStorage

pub struct PointStorage {
    x: Vec<f32>,
    y: Vec<f32>,
    z: Vec<f32>,
}

Each point is identified by a PointHandle(u32) — a lightweight typed index returned by add_point.

Point API

MethodSignatureDescription

point_pos fn point_pos(&self, handle: PointHandle) -> Vec3 Read the position of a point.

Raw Slice Access

For performance-critical code, access the underlying SoA slices directly: 

let storage = geo.point_storage();
let xs: &[f32] = storage.x_slice();
let ys: &[f32] = storage.y_slice();
let zs: &[f32] = storage.z_slice();

// Process all x-coordinates in a tight loop (SIMD-friendly)
let sum_x: f32 = xs.iter().sum();

Vertices

Vertices are topology connectors: each vertex references exactly one PointHandle and one PrimHandle. Multiple vertices can share the same point — this is the standard Houdini semantic that allows per-face UVs, split normals, and other vertex-level data on shared geometry.

Identified by VertexHandle(u32), vertices are stored contiguously and grouped by primitive. The underlying VertexStorage maintains two parallel vectors: point_refs and prim_refs. 

pub struct VertexStorage {
    point_refs: Vec<PointHandle>,
    prim_refs:  Vec<PrimHandle>,
}

Query topology through the geometry: 

let pt: PointHandle = geo.vertex_point(vtx_handle);  // which point does this vertex use?
let pr: PrimHandle = geo.vertex_prim(vtx_handle);   // which primitive owns this vertex?

Primitives

Primitives define the topology of the geometry. Currently ProcGeo supports one primitive type: Polygon, which can be either open (polyline) or closed (face), with an arbitrary vertex count. The primitive enum is dispatched statically — no vtable overhead. 

pub enum Primitive {
    Polygon(PolygonPrim),
}

pub struct PolygonPrim {
    pub vertices: SmallVec<[VertexHandle; 4]>,
    pub poly_type: PolyType,  // Open | Closed
}

Vertex handles are stored in a SmallVec<[VertexHandle; 4]> — quads and triangles (the overwhelmingly common case) are stored inline on the stack with zero heap allocation. Only polygons with 5+ vertices spill to the heap.

Each primitive is identified by a PrimHandle(u32).

Primitive API

MethodDescription
add_face(&[PointHandle]) Add a closed polygon from the given points. Creates vertices automatically.
add_polyline(&[PointHandle]) Add an open polyline from the given points.
add_polygon(&[PointHandle], PolyType) General form — specify open or closed explicitly.
num_prims() Number of primitives.
prims() Iterate over all primitives as &Primitive.
prim(handle) Get a reference to a specific primitive.
prim_vertices(handle) Get the vertex handles for a primitive.
prim_points(handle) Resolve through vertices to get the point handles for a primitive.

Building a Triangle

use procgeo::prelude::*;
use glam::Vec3;

let mut geo = Geometry::new();

let p0 = geo.add_point(Vec3::new(0.0, 0.0, 0.0));
let p1 = geo.add_point(Vec3::new(1.0, 0.0, 0.0));
let p2 = geo.add_point(Vec3::new(0.0, 1.0, 0.0));

let face = geo.add_face(&[p0, p1, p2]);

assert_eq!(geo.num_points(), 3);
assert_eq!(geo.num_prims(), 1);
assert_eq!(geo.num_vertices(), 3);

Typed Handles

PointHandle, VertexHandle, and PrimHandle are distinct newtypes wrapping u32. They are defined via a macro to ensure consistent API while preventing accidental misuse — you cannot pass a PointHandle where a PrimHandle is expected. 

// This compiles:
let pos = geo.point_pos(point_handle);

// This does NOT compile — type mismatch at compile time:
// let pos = geo.point_pos(prim_handle);
//                        ^^^^^^^^^^^ expected PointHandle, found PrimHandle

Each handle provides from_index(usize) and index() -> usize for conversion. Handles are Copy, Eq, Ord, and Hash — safe and efficient to store in collections. 

let h = PointHandle::from_index(42);
assert_eq!(h.index(), 42);
assert_eq!(format!("{}", h), "PointHandle(42)");

Capacity

When you know the approximate size of your geometry ahead of time, pre-allocate to avoid repeated reallocation: 

// Pre-allocate for ~10,000 points and ~5,000 primitives
let mut geo = Geometry::with_capacity(10_000, 5_000);

// Vertex storage is estimated at prims * 4 (quad assumption)
// Point and vertex storage pre-allocate; attributes and groups start empty

BBox

BBox is an axis-aligned bounding box defined by min/max corners. It is computed directly from SoA point data for efficiency. 

pub struct BBox {
    pub min: Vec3,
    pub max: Vec3,
}
MethodDescription
empty()Create an inverted (empty) bbox. Any expand_point call makes it valid.
new(min, max)Create a bbox from explicit corners.
expand_point(p)Grow the box to include point p.
expand_bbox(other)Grow the box to include another bbox.
center()Returns the center point of the box.
size()Returns the size vector (max - min).
contains(p)Test if a point is inside the box.
intersects(other)Test if two bounding boxes overlap.
is_valid()True when min ≤ max on all axes.

let bb = geo.bounding_box();
if bb.is_valid() {
    println!("Center: {:?}, Size: {:?}", bb.center(), bb.size());
}

Math

ProcGeo re-exports core math types from glam and provides Houdini-style helper functions.

Re-exported Types

TypeDescription
Vec2, Vec3, Vec42D, 3D, and 4D float vectors
Mat3, Mat43x3 and 4x4 matrices

Helper Functions

FunctionSignatureDescription
fit fn fit(value, old_min, old_max, new_min, new_max) -> f32 Remap a value from one range to another. Does not clamp — extrapolates linearly outside the input range.
efit fn efit(value, old_min, old_max, new_min, new_max) -> f32 Clamped remap. Like fit but output is clamped to [new_min, new_max].
smooth fn smooth(value, min, max) -> f32 Hermite smooth-step: maps a value in [min, max] to [0, 1] with smooth acceleration/deceleration. Clamped outside the range. 
use procgeo::core::math::{fit, efit, smooth};

let t = fit(0.5, 0.0, 1.0, 0.0, 100.0);     // 50.0
let t = efit(2.0, 0.0, 1.0, 0.0, 100.0);    // 100.0 (clamped)
let s = smooth(0.5, 0.0, 1.0);              // 0.5 (smooth midpoint)
