I/O Formats

Reading and writing geometry to files.

Overview

The procgeo-io crate provides a plugin-based I/O system. Formats are registered by feature flag and dispatched by file extension. Each format implements the GeometryWriter and/or GeometryReader traits.

FormatExtensionReadWriteFeature
Wavefront OBJ.objYesYesobj
glTF 2.0 / GLB.glb--Yesgltf

Both formats are enabled by default in the umbrella procgeo crate.

File-Based API

The simplest way to read and write geometry. The format is selected automatically from the file extension.

use procgeo::io::{write_file, read_file};
use std::path::Path;

// Write geometry to OBJ
write_file(&geo, Path::new("output.obj"))?;

// Write geometry to GLB
write_file(&geo, Path::new("output.glb"))?;

// Read geometry from OBJ
let geo = read_file(Path::new("model.obj"))?;

Trait Interface

Format implementations use two traits, making the system extensible:

pub trait GeometryWriter {
    fn write(&self, geo: &Geometry, writer: &mut dyn Write) -> Result<(), IoError>;
    fn extensions(&self) -> &[&str];
}

pub trait GeometryReader {
    fn read(&self, reader: &mut dyn Read) -> Result<Geometry, IoError>;
    fn extensions(&self) -> &[&str];
}

Error Handling

pub enum IoError {
    Io(std::io::Error),          // File system errors
    Parse(String),               // Malformed input data
    UnsupportedFormat(String),   // Unknown file extension
}

Wavefront OBJ

Writing

The OBJ writer outputs:

  • v records for point positions
  • vn records if the "N" point attribute exists
  • f records for closed polygons (1-indexed with optional //normal references)
  • l records for open polylines

Reading

The OBJ reader parses v, vn, f, and l records. Vertex normals are stored as the "N" point attribute. Other OBJ features (materials, texture coordinates, object groups) are currently ignored.

Round-Trip

use procgeo::prelude::*;

// Generate geometry
let geo = generate(&SphereSop, &SphereParams::default())?;
let geo = geo.apply(&NormalSop, &NormalParams::default())?;

// Write to OBJ
procgeo::io::write_file(&geo, Path::new("sphere.obj"))?;

// Read back
let loaded = procgeo::io::read_file(Path::new("sphere.obj"))?;
assert_eq!(loaded.num_points(), geo.num_points());

glTF 2.0 / GLB

Writing

The GLB writer produces a binary glTF 2.0 file with:

  • Positions from point storage
  • Fan-triangulated indices (polygons are split into triangles)
  • Normals from the "N" attribute, if present
  • Vertex colors from the "Cd" attribute, if present
GLB export is write-only. glTF reading is not yet implemented.

Binding I/O

Each binding exposes I/O functions:

WASM

const objString = geo.toObj();      // OBJ as string
const glbBytes  = geo.toGlb();      // GLB as Uint8Array

Node.js

const { writeObj, writeGlb } = require('@procgeo/core');

writeObj(geo, 'output.obj');
writeGlb(geo, 'output.glb');

Python

import procgeo

procgeo.write_obj(geo, "output.obj")
procgeo.write_glb(geo, "output.glb")

Feature Selection

Disable unwanted formats to reduce binary size:

# Cargo.toml — OBJ only, no glTF
[dependencies]
procgeo = { version = "0.1", default-features = false, features = ["creation", "obj"] }
