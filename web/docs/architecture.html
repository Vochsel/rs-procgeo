Architecture

How ProcGeo is structured, from crate layout to runtime performance.

Crate Layout

ProcGeo is a multi-crate workspace. The umbrella crate re-exports everything through a prelude module; downstream consumers only need procgeo as a dependency.

procgeo (umbrella — re-exports + prelude)
 ├── procgeo-core     Geometry model, attributes, groups, math
 ├── procgeo-sops     SOP implementations (feature-gated)
 ├── procgeo-io       Format readers/writers (OBJ, glTF)
 └── bindings/
      ├── procgeo-node   Node.js (napi-rs)
      ├── procgeo-py     Python (PyO3)
      └── procgeo-wasm   WebAssembly (wasm-bindgen)

procgeo-core owns the canonical Geometry struct and has zero dependencies on the SOP or I/O crates. procgeo-sops and procgeo-io depend only on core. The binding crates depend on all three but contain no business logic of their own.

Design Principles

  1. Stateless SOPs — every SOP is a pure function: execute(inputs, params) -> Result<Geometry>. No mutation of inputs. This enables caching, parallelism, and trivial undo.
  2. SoA Memory Layout — point positions are stored as three contiguous Vec<f32> arrays (x, y, z) rather than an array-of-structs. This is SIMD-friendly and maximises cache utilisation during component-wise iteration.
  3. Typed Handles — PointHandle(u32), VertexHandle(u32), PrimHandle(u32) are distinct newtypes that prevent index confusion at compile time. You cannot accidentally pass a point index where a primitive index is expected.
  4. Feature-Gated Compilation — each SOP category is a Cargo feature flag. The umbrella crate enables all features by default, but downstream consumers can cherry-pick only the SOPs they need for smaller binaries.
  5. Thin Bindings — the Node.js, Python, and WASM wrapper crates contain zero business logic. All geometry processing stays in Rust; bindings only marshal data across the FFI boundary.
  6. Houdini Semantics — four attribute classes (point, vertex, primitive, detail), group-based selection, and topology expressed through vertices mirror Houdini's geometry model.

The SOP Trait

Every SOP implements the same trait:

pub trait Sop {
    type Params: Default;

    fn execute(
        &self,
        inputs: &[&Geometry],
        params: &Self::Params,
    ) -> Result<Geometry, SopError>;

    fn input_count(&self) -> (usize, usize);
    fn name(&self) -> &'static str;
}

Input Conventions

  • Generator SOPs (Box, Grid, Sphere, ...) take 0 inputs. Use the generate() helper to call them with an empty input slice.
  • Filter SOPs (Transform, Normal, Blast, ...) take 1 input.
  • Multi-input SOPs (Merge, CopyToPoints, ...) take 2+ inputs. input_count() returns (min, max).

Chaining with GeometryExt

The GeometryExt trait adds an .apply() method to Geometry for fluent chaining:

let result = generate(BoxSop, BoxParams { size: vec3(2.0, 1.0, 1.0), ..default() })
    .apply(TransformSop, TransformParams { translate: vec3(0.0, 1.0, 0.0), ..default() })
    .apply(NormalSop, NormalParams::default())?;

Performance Architecture

  • SoA point layout enables component-wise SIMD — iterate one f32 lane at a time without struct padding.
  • glam provides SSE2/SSE4.1/NEON-accelerated vector and matrix math out of the box.
  • SmallVec<[VertexHandle; 4]> inlines the vertex list for triangles and quads on the stack, avoiding heap allocation for the common case.
  • BitVec groups use word-at-a-time boolean operations — union, intersection, and complement run at memory bandwidth rather than per-element.
  • Pre-allocated capacity — SOPs estimate output size and reserve capacity up front to avoid incremental reallocation.

Error Handling

ProcGeo uses three error enums, one per crate, all derived with thiserror. SopError wraps CoreError via #[from] so core errors propagate automatically.

CoreError

pub enum CoreError {
    AttributeNotFound(String),
    AttributeTypeMismatch(String),
    GroupNotFound(String),
    InvalidHandle,
    InvalidTopology,
}

SopError

pub enum SopError {
    WrongInputCount { expected_min: usize, expected_max: usize, got: usize },
    InvalidParam(String),
    Core(CoreError),    // #[from] — auto-converts
    Other(String),
}

IoError

pub enum IoError {
    Io(std::io::Error),          // #[from] — auto-converts
    Parse(String),
    UnsupportedFormat(String),
}

Feature Flags

Each SOP category and I/O format is gated behind a Cargo feature. The umbrella procgeo crate enables all features by default.

Feature Crate Description
creation procgeo-sops Box, Grid, Line, Circle, Sphere, Tube, Torus
transform procgeo-sops Transform SOP
normals procgeo-sops Normal SOP
merge procgeo-sops Merge SOP
attributes procgeo-sops Attribute Create/Delete/Promote/Rename
groups_sops procgeo-sops Group Create/Combine
delete procgeo-sops Blast, Delete
copy procgeo-sops Copy to Points
reshape procgeo-sops Subdivide, PolyExtrude, Smooth, Clip
scatter procgeo-sops Scatter
topology procgeo-sops Sort, Fuse, Connectivity, Resample, Reverse
measure_sops procgeo-sops Measure
utility_sops procgeo-sops Enumerate, Null
color procgeo-sops Color
obj procgeo-io Wavefront OBJ read/write
gltf procgeo-io glTF 2.0 / GLB write
To use only specific features, disable default features and opt in: 
[dependencies]
procgeo = { version = "0.1", default-features = false, features = ["creation", "transform", "obj"] }
